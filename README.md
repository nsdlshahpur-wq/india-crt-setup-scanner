# India CRT Setup Scanner

A Streamlit dashboard for the Monthly (1M) → Daily (1D) CRT scanner and historical backtest.

## Dashboard

The app includes the CRT Scanner, historical Backtest and an in-app CRT AI Assistant. The assistant can explain the strategy and interpret the latest scanner/backtest data available in the current app session.

## Strategy overview

1. **M1:** Previous completed month's High–Low liquidity range.
2. **M2:** Sweep exactly one side of M1 and close back inside the full M1 range.
3. **M3:** Use current-month completed Daily candles for CHoCH and entry-zone analysis.
4. After CHoCH, look for a retest in one of FVG, IFVG, OB or BOB, followed by a directional Daily confirmation close.
5. **Stop loss:** Actual M2 sweep-candle extreme. **Target:** Opposite M1 liquidity.
6. Only a fresh confirmation on the latest completed Daily candle is labelled BUY/SELL. Older untriggered opportunities are shown as missed/stale, not fresh entries.

These are explicit mechanical OHLC rules. They may differ from discretionary chart interpretations and do not guarantee profitable signals.

## Historical backtesting and reproducibility

- Backtest universe: current BSE EQ scrip master (Yahoo Finance `.BO` tickers where data is available).
- Default test request: 5 years of Daily OHLC, ₹100,000 starting capital, 1% equity risk per trade.
- Signals are generated by evaluating the unchanged scanner against an as-of prefix ending on each historical completed candle. No later candle is visible when a signal is created.
- Entry is the confirming Daily candle close. SL/target checks start on the following candle. If one candle touches both SL and target, the result is marked ambiguous and conservatively priced at SL.
- Position size is risk-budget based and capped by available capital; simultaneous exposure is capped to available equity and duplicate overlapping positions in the same symbol are skipped.
- Default estimated costs are 12 bps transaction charges and 5 bps slippage per side; both are editable. These are approximations, not a contract-note tax calculator.
- The first 80 Daily bars per symbol are warm-up, so the effective test window begins after that warm-up. Insufficient history and unavailable tickers are reported.
- Win rate excludes ambiguous and end-of-data open trades. Profit factor includes conservative ambiguous P&L. The equity curve and drawdown are based on realised exits; open trades are marked to the last available close in final P&L.

**Important:** The BSE universe is the current exchange master, not historical point-in-time constituents. Delisted stocks and past constituent changes are missing (survivorship bias). Yahoo Finance history can be incomplete, adjusted or unavailable. Results are research estimates, not guaranteed or executable performance.

## Market data and limitations

- Daily OHLC history is downloaded from Yahoo Finance through `yfinance`.
- Yahoo Finance is an unofficial data source. Prices may be delayed, incomplete, adjusted, throttled or unavailable.
- The displayed LTP is the latest downloaded Daily close, not a live tick quote.
- Verify every candidate on a broker or TradingView chart before making a trading decision.
- The scanner is read-only and does not place, modify or cancel orders.

## Validation

GitHub Actions runs Python compilation and offline pytest checks on pushes and pull requests. Live market-data smoke checks are non-blocking because the external data provider may be unavailable.

## Main files

- `app.py` — Streamlit dashboard with Scanner, Backtest and CRT AI Assistant tabs.
- `scanner.py` — Monthly sweep/reclaim, Daily CHoCH, FVG/IFVG/OB/BOB zones, retest, entry and outcome logic.
- `backtest.py` — no-look-ahead historical simulation, position sizing, costs, metrics and equity curve.
- `test_backtest.py` — offline tests for exits, costs, sizing, metrics and as-of signal evaluation.
- `data_fetch.py` — Yahoo Finance daily OHLC downloader.
- `universe.py` — NSE/BSE stock and index universe.
- `test_scanner.py`, `test_crt_strategy_rules.py`, `test_choch_reference.py`, `test_data_fetch.py`, `test_app.py` — core scanner tests.

## Scheduled CRT monitoring bot

- `crt_bot.py` runs the existing BSE Monthly-Daily CRT scanner in read-only mode.
- `.github/workflows/crt-bot.yml` schedules a scan every 30 minutes on weekdays during the approximate Indian cash-market session (UTC cron).
- Telegram alerts require repository Actions secrets `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID`.
- Optional AI Hindi summary requires `OPENAI_API_KEY`; without it the deterministic CRT alert still works.
- GitHub Actions is a scheduled, best-effort runner, **not a continuously running 24/7 server**. Runs can be delayed, quotas apply, and scans do not execute on weekends/holidays. For true always-on monitoring, deploy the same script on an always-on VPS/container and use a persistent database/volume for deduplication state.
- This bot never places or modifies orders. Do not add broker trading credentials to this workflow.

## Daily CRT Hybrid AI and full-market ensemble

- The **CRT AI Lab** is integrated in the `main` branch at `pages/3_CRT_AI_Lab.py`. It loads the public NIFTY50 1-minute history, rebuilds Daily OHLC and tests the existing Monthly-Daily CRT rules.
- The main scanner supports **All India stocks + indices** (NSE EQ + BSE EQ + indices with an explicit Yahoo Finance ticker mapping), as well as NSE-only and index-only scans.
- The main app's CRT Multi-AI ensemble uses three independent classifiers: Random Forest, Extra Trees and Histogram Gradient Boosting. Their probabilities are combined with equal-weight soft voting.
- The ensemble is trained from completed, historical CRT WIN/LOSS trades generated by the five-year BSE EQ backtest. It then scores only fresh Stage-3 confirmed BUY/SELL setups found in the next full-market scan. Waiting, stale, ambiguous and non-entry stages are not assigned a success probability.
- Features are available at entry time: direction, stop/target distance, reward-to-risk, FVG/IFVG/OB/BOB, M1 range, sweep depth, CHoCH distance, zone width and entry month. Future exit fields are labels only and never features.
- Model validation is chronological (75% train / 25% unseen test). Individual model scores, ensemble accuracy, balanced accuracy and Brier score are shown. At least 45 decisive closed trades and 10 examples of each outcome are required; otherwise the app reports insufficient data.
- To activate ensemble scoring in a fresh app session: run **Backtest → Run 5-Year BSE Backtest**, wait for training, then run **CRT Scanner → All India stocks + indices → Scan market**. The trained model is held in the current Streamlit session; retrain after restarting the app.
- The Gemini-powered CRT AI Assistant remains a separate language assistant for explaining strategy and current scan/backtest data. Its API key is optional and must be stored in Streamlit Secrets, never in Git.
- All model probabilities are research estimates, not calibrated guarantees or order signals. Current exchange constituents and Yahoo Finance coverage have survivorship/data-quality limitations. Validate out-of-sample and in paper trading before relying on them.
